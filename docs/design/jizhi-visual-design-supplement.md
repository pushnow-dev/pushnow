# 即知 App 视觉设计补充

> 版本：v1
> 日期：2026-09-12
> 用途：补充 App 页面视觉方向、配色、组件约束和后续设计图生成依据。

## 1. 设计方向

即知不应做成一个蓝色通知 App。蓝色可以保留在 App 图标和品牌识别中，但不作为大面积 UI 主题色。

推荐方向：

**GitHub Neutral + Reminder Amber**

关键词：

- 克制
- 信息密度高
- 类 GitHub 通知流
- 黑白灰为主体
- 琥珀色表达时间和提醒
- 红色只表达紧急
- 蓝色只保留在 Logo 和极少数系统点缀

## 2. Logo 与 UI 颜色关系

App Logo 可以继续保持之前的蓝色铃铛视觉。Logo 是品牌入口，不要求 App 内所有组件都跟随蓝色。

规则：

- Logo：保留蓝色或蓝色渐变。
- App 主界面：以黑白灰为主。
- 蓝色不用于大面积背景、底部 Tab 胶囊、列表卡片或主要按钮。
- 蓝色可少量用于未读点、链接、可点击文本，且不应成为页面主感受。

这样能保留品牌识别，同时避免界面过冷、过杂、过像通用 SaaS。

## 3. 核心色板

| 用途 | 色值 | 说明 |
| --- | --- | --- |
| 页面背景 | `#FFFFFF` | 主背景 |
| 分组背景 | `#F6F8FA` | 类 GitHub muted background |
| 卡片背景 | `#FFFFFF` | 列表项和内容块 |
| 分割线 | `#D1D9E0` | 细边框、列表分隔 |
| 主文字 | `#1F2328` | 标题和主要信息 |
| 次级文字 | `#59636E` | 来源、时间、说明 |
| 强调黑 | `#25292E` | 当前选中、主按钮、重要控件 |
| Logo 蓝 | `#218BFF` / `#0969DA` | 仅品牌和少量链接状态 |
| 提醒琥珀 | `#9A6700` | 定时、延迟、待提醒 |
| 提醒浅底 | `#FFF8C5` | 提醒 badge 背景 |
| 紧急红 | `#D1242F` | P0、错误、危险 |
| 紧急浅底 | `#FFEBE9` | P0 badge 背景 |
| 成功绿 | `#1A7F37` | 已确认、已启用，仅少量使用 |

## 4. 色彩使用比例

建议比例：

- 黑白灰：85%
- 提醒琥珀：8%
- 紧急红：3%
- 成功绿：2%
- Logo 蓝 / 链接蓝：2%

禁止：

- 每个分类使用不同大色块。
- 每个来源使用彩色头像。
- 大面积蓝色按钮和蓝色 Tab 背景。
- 页面同时出现蓝、红、黄、绿、紫等多个强饱和色。

## 5. 导航与标题处理

主页面不应使用大标题单独占据一整行。即知的核心是快速浏览消息，顶部空间应让给筛选和内容。

### 主页面

适用页面：

- 收件箱
- 订阅
- 发现来源
- 提醒计划

处理规则：

- 不使用大号标题。
- 如果需要标题，放在导航栏中间，小号居中。
- 页面状态主要通过底部 Tab 和筛选条表达。
- 顶部区域优先放操作和筛选：选择、搜索、添加、筛选 chip。

### 详情页面

适用页面：

- 事项详情
- 安排提醒
- 来源详情
- 频道详情

处理规则：

- 可以使用居中小标题。
- 标题不做超大字号。
- 内容从导航栏下方尽快开始。

## 6. 收件箱设计

收件箱应优先参考 GitHub Notifications 的结构。

布局：

- 顶部：选择按钮、搜索、添加。
- 第二行：筛选 chip。
- 主体：通知列表。
- 底部：Tab bar。

列表项结构：

- 左侧：事件类型图标，使用黑灰线性图标。
- 未读：独立蓝色小圆点。
- 第一行：来源 / 分类 / 主题。
- 第二行：粗体事项标题。
- 第三行：摘要或最新状态。
- 右侧：时间。
- 状态 badge：仅在必要时出现。

收件箱不使用大卡片堆叠。列表项以白底、分隔线和左侧状态建立结构。

## 7. 筛选 Chip

筛选 chip 应保持低饱和。

默认：

- 背景：`#F6F8FA`
- 文字：`#59636E`
- 边框：可无或 `#D1D9E0`

选中：

- 背景：`#25292E`
- 文字：`#FFFFFF`

示例：

- 全部
- 未读
- 新到结果
- 即将提醒
- P0/P1
- 来源

不建议给每个 chip 使用独立颜色。

## 8. 底部 Tab

底部 Tab 应轻量、清晰，不做强烈蓝色主题。

建议结构：

- 胶囊型白色或浅灰容器。
- 当前项使用浅灰选中底。
- 当前项图标和文字使用 `#25292E` 或极少量 Logo 蓝。
- 未选中项使用 `#59636E`。

Tab 数量建议：

- 收件箱
- 订阅
- 发现
- 提醒

如果后续希望更简洁，也可以合并为：

- 信息
- 订阅
- 提醒

## 9. 状态表达

### 未读

- 使用蓝色小圆点。
- 不改变整行背景。

### 定时 / 延迟提醒

- 使用琥珀色文字和浅黄色背景 badge。
- 示例：`5 小时后`、`今晚 20:00`、`每周五 18:00`。

### P0 / 紧急

- 使用红色小 badge。
- 不让整行变红。
- P0 只出现在真正需要立即注意的事项上。

### 已确认 / 已启用

- 使用小绿点或绿色文本。
- 不使用大面积绿色背景。

### 已取消 / 已归档

- 使用灰色 muted 状态。
- 不使用紫色，除非后续有非常明确的完成状态体系。

## 10. 图标与来源头像

图标风格：

- 线性图标。
- 类 GitHub Octicons / SF Symbols。
- 主要为黑灰。

来源头像：

- 不默认使用彩色机器人头像。
- 私人 Agent 可使用简洁单色符号。
- 公开频道可使用单色图标加浅灰圆底。

只有 App Logo 可以保持蓝色高识别度。

## 11. 页面补充方向

### 收件箱

目标：像 GitHub 通知流一样快速判断发生了什么。

重点：

- 不放大标题。
- 列表密度更高。
- 不用彩色分类。
- 未读点、P0、提醒时间是唯一重点。

### 事项详情

目标：清楚展示结果和提醒状态。

重点：

- 顶部小标题。
- 提醒 banner 用琥珀色。
- 内容块保持白底和细边框。
- 主操作按钮使用深色，而不是蓝色。

### 安排提醒

目标：让用户明确“什么时候提醒、用什么方式提醒”。

重点：

- 当前选择用深色 chip。
- 时间选择器保持浅灰。
- 保存按钮使用深色。
- 开关可以保留 iOS 系统样式，但避免过多蓝色时，可改为深色或系统默认。

### 订阅

目标：管理来源，不做市场感。

重点：

- 不放大标题。
- 个人接入和已订阅使用列表分组。
- 状态用小点和文字，不用大色块。

### 发现来源

目标：像可订阅的信息源目录，不像彩色应用商店。

重点：

- 不使用彩色频道卡片。
- 频道列表以名称、样例、频率、状态和订阅按钮为主。
- 筛选 chip 使用 neutral 风格。

### 提醒计划

目标：像日程化的通知列表。

重点：

- 不放大标题。
- 时间作为列表左侧主锚点。
- 提醒 badge 使用琥珀色。
- 取消记录使用灰色弱化。

## 12. 下一版设计图生成要求

如果继续生成 v4 设计图，应使用以下约束：

- 保留蓝色 Logo 作为品牌识别，但页面 UI 不以蓝色为主题。
- 主页面不要大标题单独占行。
- 收件箱第一屏不显示大号「信息」。
- 订阅、发现来源、提醒也不要大号标题；如需标题，使用导航栏居中小标题。
- 分类不使用彩色 chip。
- 来源图标和事项图标使用黑灰。
- 主按钮使用深色 `#25292E`。
- 提醒状态统一使用琥珀色。
- 紧急状态只用红色小 badge。
- 整体参考 GitHub Notifications，而不是常规蓝色 SaaS App。
